# 媒体服务器同步：播放时自动上报，首页按模式导入

连接 Emby、Jellyfin、Plex、飞牛影视或极影视后，zPlayer 会在播放对应服务器来源的媒体时，尝试把播放状态和进度回传到服务器。这个过程不需要你在播放器里另外点击“同步”。

不过这里有两件容易混淆的事：**播放进度上报**和**把服务器历史/收藏导入首页**。前者跟着播放发生，后者主要取决于连接时有没有开启“媒体库模式”。

## 播放时会发生什么？

| 播放阶段 | zPlayer 会做什么 |
| --- | --- |
| 开始播放 | 向服务器报告开始播放，并建立本次播放上下文 |
| 播放过程中 | 按服务实现上报当前位置；Emby 播放中大约每 10 秒上报一次，其他服务的节奏可能不同 |
| 暂停 | 尝试提交当前进度 |
| 停止、切换片源或播放结束 | 提交最终位置，并报告停止播放 |
| 关闭播放器 | 仍会尝试提交最后进度；为了让窗口立即关闭，收尾网络请求会在后台完成 |

因此，刚关闭播放器就立刻打开服务器网页时，偶尔需要等一会儿或刷新一次页面。播放能开始，只能说明“读取”权限正常，并不代表当前账户拥有更新观看进度的权限。

## 使用前先检查这四件事

1. 在[文件服务](/docs/media/file-services)中确认服务器地址、账户和密码正确，来源没有被停用。
2. 确认登录账户有更新播放历史/播放状态的权限。有些共享服务器允许播放，但不允许写入进度。
3. 如果同一部作品有本地、NAS 和服务器多个片源，播放前确认当前选中的确实是服务器片源。
4. 确认服务器媒体与 zPlayer 的标题、季数、集数或媒体 ID 匹配；匹配错误时，进度可能被写到另一条记录，或者无法导入首页。

## 媒体库模式和直连模式的区别

连接媒体服务器时，部分服务会显示“媒体库模式”开关。它决定 zPlayer 是把服务器当作一个完整片库读取，还是主要按目录按需浏览。

| 模式 | 适合的场景 | 与同步有关的行为 |
| --- | --- | --- |
| **直连模式** | 浏览别人分享的服务器、只按需打开内容 | 播放服务器媒体时仍可上报播放状态；不会主动把整个服务器片库、历史和收藏整理进 zPlayer 首页 |
| **媒体库模式** | 自己搭建并管理、希望完整管理服务器片库 | 会读取服务器媒体信息；首页刷新时还会尝试把服务器历史和收藏合并到 zPlayer 的本地记录与首页 |

媒体库模式的行为可以理解成类似 Infuse 的媒体库模式：zPlayer 会主动获取服务器中的媒体信息，而不是等你点开某个目录才读取一个文件。

::: warning 非自建服务器优先用直连模式
媒体库模式会请求服务器中的大量媒体信息。对于共享或非自建服务器，这可能让加载和刮削变慢，也可能触发服务端限流甚至账号风险。除非管理员明确允许，通常建议关闭媒体库模式；需要完整管理自建片库时再开启。
:::

## 首页中的历史和收藏什么时候会更新？

只有媒体库模式来源参与首页的服务器历史/收藏合并。回到首页或触发首页刷新时，zPlayer 会尝试读取服务器的播放历史和收藏，并把能对应到本地媒体的项目合并进来。

这意味着：

- 服务器里有一部媒体，但 zPlayer 本地没有对应条目，它不会自动凭空生成一个本地记录。
- 直连模式下播放进度可以正常上报，但不要期待服务器的全部历史和收藏自动出现在首页。
- 服务器暂时离线时，本次合并会跳过，已有的本地内容不会因此全部清空。

## 已观看、未观看和收藏

在媒体详情中把媒体标记为“已观看”或“未观看”时，zPlayer 会先更新本地状态，同时尝试调用媒体服务器的对应接口。批量标记时，某一个远程项目失败通常不会阻断其他项目；如果服务器没有写入权限，本地状态仍可能已经改变。

Emby、Jellyfin、飞牛影视和极影视支持相应的观看状态/收藏同步能力；Plex 可以同步播放进度和观看状态，但没有与其他服务相同的收藏回写能力。具体结果还取决于服务器版本、账户权限和当前媒体是否能匹配到服务器项目。

媒体详情里的手动标记属于媒体操作本身，具体入口请看[媒体详情](/docs/media/home/media-detail)；本页只说明它与服务器同步的关系。

## 进度没有同步，按这个顺序查

### 能播放，但服务器没有进度

先检查当前账户是否有写入播放状态的权限，再确认播放的来源确实是媒体服务器。随后播放一小段、主动停止，等待几秒后刷新服务器网页。如果只有某一个服务器来源失败，优先检查这个来源的连接，不要清空全部本地历史。

### 服务器有记录，但首页没有

确认该来源开启了媒体库模式，然后回到首页等待刷新。还要检查服务器媒体能否对应到 zPlayer 的本地媒体；只有服务器返回的项目与本地条目匹配，历史或收藏才有地方落下。

### 进度写到了错误的媒体

通常是同名作品、季数或集数匹配不准确，或者多个来源中选错了片源。打开媒体详情修正元数据，之后再用正确来源播放一次。连接管理中的目录也不要把电影、电视剧混合的公共根目录直接作为一个来源，相关规则见[文件服务](/docs/media/file-services)。

### 关闭播放器后状态晚一点出现

这是正常的收尾行为：窗口关闭不等待网络请求，最后一次服务器更新会在后台完成。若等待后仍没有结果，再按“能播放但服务器没有进度”的顺序检查权限和来源。

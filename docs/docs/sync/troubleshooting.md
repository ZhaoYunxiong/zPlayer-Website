# 同步异常排查：先判断是哪一种同步

“同步失败”经常不是同一个问题：可能是外部账号没有授权，也可能是媒体服务器没有写入权限，或者两边根本没有认成同一部作品。建议先不要连续点击“立即同步”，按下面的顺序定位。

## 先做一次小范围检查

1. 只选一部标题、年份、季数和集数都明确的媒体测试。
2. 确认它能在 zPlayer 中正常播放，并且本地历史已经产生。
3. 如果是 Bangumi/Trakt，检查总开关、登录状态和拉取/推送方向。
4. 如果是媒体服务器，检查当前播放的来源、账户写入权限和媒体库模式。
5. 分别查看本地、服务器或外部网站的结果，不要只看首页一处。

## 完全没有同步

### Bangumi 或 Trakt

先打开 `设置 → 首页 → 历史记录`：

- 总开关是否真的保持打开；打开后立即关闭，通常意味着授权或功能授权检查没有通过。
- “登录验证”是否完成，授权是否已经过期或被撤销。
- “拉取播放历史”和“推送播放历史”至少有一个方向被打开。
- 测试媒体是否已经完成刮削并有正确的匹配信息。

如果只是某几部媒体没有同步，先看匹配；如果所有媒体都没有同步，再看登录、网络和授权。

### 媒体服务器

先播放一个服务器来源的媒体，主动播放一小段后停止，等待几秒再刷新服务器网页。能播放但没有进度，最常见的原因是当前账户只有读取权限，没有更新播放状态的权限。也要确认你没有误播本地或 NAS 的同名片源。

## 只推送成功，拉取没有结果

拉取不是把远端所有记录直接复制到首页，它只会更新本地已经存在并且能匹配上的媒体。

- Bangumi：检查标题、首播日期、季数和集数；当前 zPlayer 对 Bangumi 以电视剧/动漫分集为主。
- Trakt：检查本地是否有正确的 TMDB ID；只看标题相同不够。
- 媒体服务器媒体库模式：检查来源是否开启媒体库模式，以及服务器项目能否对应到本地媒体。

如果远端记录本来就没有对应的本地媒体，拉取没有变化是预期行为，不是同步失败。

## 只拉取成功，推送没有结果

先确认本地确实有已观看记录，再检查媒体的匹配信息。没有 TMDB ID、标题/年份匹配错误、季数识别错误，都会让推送找不到目标。

另外，Bangumi/Trakt 的“推送播放历史”开关只影响手动“立即同步”的推送方向；播放记录保存后的后台自动推送由服务总开关和登录状态决定。媒体服务器的播放进度则跟随服务器片源播放，不受这个外部账号开关控制。

## 本地和远端状态不一致

先确认你比较的是同一种状态：

- `00:20:30` 是播放进度，不等于“已观看”。
- Bangumi/Trakt 主要记录看过的作品或分集，不保存 zPlayer 的精确续播位置。
- 媒体服务器可能同时有播放位置和已观看标记，二者更新时机也可能不同。

如果拉取、推送两个方向都打开，当前流程会先拉取再推送。两边数据差异较大时，先关闭一个方向，确定要保留哪边的结果，再做小范围同步。

## 重复记录或同步到了错误条目

常见原因是同名作品、重制版、特别篇、季数或片源来源混在一起。处理顺序建议是：

1. 打开[媒体详情](/docs/media/home/media-detail)，确认标题、年份、季数、集数和来源。
2. 通过[TMDB 与元数据](/docs/media/home/metadata)重新刮削或编辑错误信息。
3. 如果是媒体服务器，确认播放的是正确来源，并检查媒体库模式下的服务器项目映射。
4. 暂停自动同步，用一部媒体重新测试，再扩大范围。

不要在匹配错误时反复进行双向同步，否则可能把错误状态继续写到远端。

## 登录过期或同步中途失败

授权接近过期时，zPlayer 会尝试自动刷新；如果服务端撤销了授权、网络中断或刷新失败，重新点击“登录验证”即可。同步过程中网络短暂中断时，不要马上连续点击多次，等服务恢复后用一条明确匹配的媒体重试。

如果软件提示需要内购授权，请按应用内提示处理，购买说明见[内购解锁](/docs/getting-started/unlock)。

## 反馈问题时带什么信息？

给开发者反馈时，尽量提供：

- 同步类型：Bangumi、Trakt、Emby、Jellyfin、Plex、飞牛影视或极影视；
- 媒体类型和示例：电影，或电视剧的季数、集数；
- 你执行的是拉取、推送、立即同步，还是播放时自动上报；
- 当前是直连模式还是媒体库模式；
- 发生时间、软件版本、错误提示，以及脱敏后的日志或[刮削信息导出文件](/docs/media/home/scraping)。

不要发送密码、访问令牌、Cookie 或完整的私人服务器地址。若问题只发生在某个来源，也请写清来源类型和连接方式，这比“所有同步都失败”更容易定位。

# 历史同步：把观看记录推送到平台，也能找回来

“历史同步”是一个独立页面，用来集中处理观看记录在各平台之间的推送和拉取。它和播放时自动上报进度是两件事：自动上报在播放过程中悄悄完成，历史同步则让你能看清每个来源、每一步处理了多少条记录。

## 从哪里进入

在左侧打开“历史记录”页面，页面顶部有“同步”入口，点开后就是历史同步页面。需要推送或拉取时不必先播放媒体，页面本身就可以操作。

Bangumi 和 Trakt 的登录授权在“设置 → 首页 → 历史记录”里完成；媒体服务器（Emby、Jellyfin、Plex、飞牛影视、极影视等）只要在连接管理里添加过来源，就会出现在同步列表中。

## 每个来源能做两件事

列表里的每一项代表一个可同步的来源，通常提供两个方向：

| 操作 | 作用 |
| --- | --- |
| 推送 | 把本地历史更新到远端可匹配的条目 |
| 拉取 | 把远端观看记录合并到本地历史 |

每个来源还会标注它支持的内容：有的同时支持“播放进度 · 已看状态”，有的只能同步“已看状态”。能力不同的来源，同步后的结果也会不一样。

页面顶部还有“全部推送”和“全部拉取”，会并发处理所有勾选了“参与全部同步”的空闲来源。正在同步的来源不会重复参与。

## 局域网设备之间同步 {#device-sync}

历史同步页面最上面的“局域网同步”区块是给同一局域网内的多台 zPlayer 用的：家里有台式机和笔记本，或者两台电脑分别看了不同的剧，可以用它把播放历史合并到两边，继续观看和观看状态都会跟着补上。

点开“播放历史同步”卡片就是设置入口：

| 设置 | 作用 |
| --- | --- |
| 自动同步 | 打开后，设备会在局域网内自动发现同组设备并同步 |
| 设备名称 | 在同步记录里区分是哪台设备，默认使用电脑名 |
| 同步密钥 | 同步组的密码。在一台设备上生成密钥，再把同一密钥粘贴到其他设备 |

设置改动会立即保存并生效。想马上同步一次，可以点“立即同步”，不必等自动同步的下一轮。

同步范围包括本地历史和受支持的远程来源历史，也包含没有逐次明细的旧历史摘要；媒体服务器、直链和 STRM 不参与，缺失的逐次播放明细也不会被补造出来。

卡片上能看到当前状态和上次传输的发送、接收条数：

| 状态 | 含义 |
| --- | --- |
| 未开启 | 自动同步没有打开 |
| 等待设备 | 已经在运行，但还没发现持有相同密钥的设备 |
| 已连接 N 台设备 | 找到了同组设备并能通信 |
| 正在同步… | 正在交换变更 |
| 同步异常 | 连接或写入失败，展开“同步详情”看具体原因 |

同步完成后，如果已经离开历史同步页面，主界面会弹出一条提示，显示这次发送和接收了多少条变更。找不到同组设备时提示会明确说明，而不是显示“同步失败”。

排错时按这个顺序检查：两台设备是否在同一个局域网、自动同步是否都打开、密钥是否完全一致（复制粘贴比手抄可靠）、以及系统防火墙是否拦截了 zPlayer。

## 同步过程中和结束后

同步时会显示当前进度；不需要时可以取消。取消只会停止后续批次，已经发出的请求会等它结束，已经完成的更新会保留。

结束后会显示一条结果摘要，例如：

```text
新增 12 · 更新 3 · 跳过 40 · 未匹配 5 · 失败 0
```

“未匹配”通常表示远端找不到对应的作品或剧集。常见原因是作品名称、年份、季集编号或 TMDB 匹配不一致；先在媒体详情里把资料改对，再重新同步，比反复点击更有效。

每个来源都有“记录”入口，可以查看最近 100 次的同步日志，包括时间、方向、结果和错误详情。

## 授权过期怎么办

如果某个来源显示“需要重新授权”，说明它的授权已经过期或不可用。页面会提示是否现在前往授权：

- **Trakt**：打开授权网页后会显示一个验证码，把验证码填进 Trakt 页面即可。完成前保持授权窗口打开，授权成功后点击确定保存。
- **Bangumi**：按页面提示重新完成登录授权。

授权过期后推送和拉取都会失败，重新授权完成后不需要重新配置其他选项。

## 媒体详情里的单作品同步

不想整库同步时，可以只处理一部作品。打开媒体详情，在同步入口里选择 Bangumi 或 Trakt：

- 先选择“推送到平台”还是“从平台拉取”；
- 读取远端状态并预览将要发生的变化；
- 勾选要处理的具体剧集或电影，确认后执行。

不同平台的规则不一样：Bangumi 只推送已看状态，没看完的本地项目会跳过；Trakt 从 1% 起保存续播进度，停止进度达到 80% 时可能计为已看。预览后如果账号或观看状态发生了变化，需要重新读取再确认。

## 从备份恢复本地历史

历史记录页面还提供“恢复历史记录”，用于把本地播放历史找回来：

| 方式 | 说明 |
| --- | --- |
| 从备份恢复 | 使用自动生成的备份文件恢复 |
| 从数据库重建 | 查找本机残留的观看信息重建记录，可能包含媒体服务器同步过来的观看状态 |

恢复结果会和当前历史合并，并保留当前的播放进度；应用更改前软件会自动再备份一次。软件在每天首次保存、清空历史以及恢复前都会自动备份，保留最近 14 份每日备份和 20 份操作备份。

重建出来的记录属于估算历史，无法找回完整的观看明细，日期和播放次数可能不准确。

恢复之后如果发现结果不符合预期，可以执行“撤销上次历史恢复”：它会移除上次恢复新增的记录，并还原补回的观看明细。恢复之后又播放或修改过的记录会保留。

## 和自动同步的关系

历史同步页面适合手动补一次、检查结果或修正错误；日常使用时，打开 Bangumi、Trakt 的推送或拉取开关后，软件会在保存播放记录后自动尝试同步。两套入口操作的是同一批记录，不会产生两份历史。

同步的前提是把作品认成同一部。名称、年份、季数和 TMDB 匹配不正确时，远端可能找不到对应条目。相关排查见[同步异常排查](/docs/sync/troubleshooting)。

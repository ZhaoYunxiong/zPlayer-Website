# 投屏与局域网共享：先确认数据流向

zPlayer 同时提供投屏、DLNA 接收和多种局域网共享服务。它们看起来都和“其他设备”有关，但方向并不相同。

| 功能 | 数据方向 | 典型用途 |
| --- | --- | --- |
| DLNA 投屏 | zPlayer → 电视或其他渲染设备 | 把当前媒体放到大屏播放 |
| DLNA 媒体渲染 | 手机或其他控制端 → zPlayer | 让这台电脑作为可发现的播放设备 |
| 文件/媒体共享 | 其他设备 → 这台电脑上的 zPlayer 内容 | 在局域网读取或播放本机媒体 |
| WebDAV、FTP 服务 | 其他客户端 → 这台电脑 | 按对应协议访问共享内容 |

## 把媒体投到电视

1. 让电脑和电视或盒子处于同一局域网，并在接收设备上开启 DLNA。
2. 在 zPlayer 的投屏相关入口搜索设备。
3. 选择接收设备，再选择或确认要播放的媒体。
4. 先用一个普通 MP4 文件测试播放、暂停和进度控制。

如果投的是本地文件，zPlayer 需要让接收设备能从电脑取得媒体数据；因此 Windows 防火墙、访客网络隔离或路由器的客户端隔离都可能导致“能发现设备但无法播放”。远程片源还可能因为接收设备不支持其鉴权方式而失败。

## 让 zPlayer 接收 DLNA 播放

在“设置 → 投屏”中设置设备名称，并开启 DLNA 投屏/接收相关开关。启用“自动播放投屏而不用询问”后，其他控制端发送内容时会直接开始播放；共享网络中建议保留确认，避免误投。

## 开启局域网共享服务

“设置 → 媒体服务器”中可以分别配置文件传输、媒体传输、WebDAV、FTP 和 DLNA 服务。默认端口如下：

| 服务 | 默认端口 |
| --- | ---: |
| 媒体传输 | 62101 |
| 文件传输 | 62102 |
| FTP | 62103 |
| DLNA | 62104 |
| WebDAV | 62106 |

WebDAV 的访问路径使用 `/dav`。需要账号密码的服务应设置独立凭据，不要复用 Microsoft 账户、NAS 管理员或邮箱密码。

端口只应开放在可信局域网中。若 Windows 弹出防火墙提示，只允许当前确实需要的“专用网络”；不要为了省事把这些服务直接暴露到公网。

## 常见问题

- 搜不到电视：确认同一网段、接收端 DLNA 已开启，并关闭路由器的访客隔离。
- 能发现但播放失败：先换普通 H.264/AAC MP4，排除接收端不支持编码或远程鉴权。
- 手机打不开共享地址：检查服务开关、电脑 IP、端口和 Windows 防火墙。
- 端口被占用：在设置中换一个未使用的端口，并同步修改客户端地址。
- 休眠后失联：电脑进入睡眠时共享服务无法响应，需要唤醒后重新连接。

从另一台设备连接 zPlayer 提供的 DLNA 来源，则属于[媒体服务器连接](/docs/media/connections/media-servers#dlna)，不是本页的投屏方向。

# 网络与 TMDB：先判断是网络、服务还是匹配

网络问题不要一上来只改 TMDB。先问自己两个问题：

- 是所有在线功能都失败，还是只有 TMDB、某个站点或某个媒体服务器失败？
- 本地文件能不能正常播放？

本地文件播放通常不依赖 TMDB。TMDB 暂时不可访问时，可以先完成文件服务和播放器测试。

## 先做一个外部对照

1. 用 Windows 浏览器打开目标服务的网页或地址；
2. 确认系统时间、日期和时区正确；
3. 确认 Windows 防火墙、杀毒软件或公司网络没有拦截 zPlayer；
4. 如果是 NAS、Emby、Jellyfin 或 Plex，确认服务端本身正在运行；
5. 如果只有一个在线站点失败，先把它当作站点失效或接口变更处理。

浏览器能打开网页，不一定代表对应的 API、媒体流或图片域名都能访问。反馈时要写清楚失败的是网页、搜索、海报还是实际播放。

## zPlayer 代理设置

入口是“设置 → 其它 → 网络代理”：

| 模式 | 适合怎么测试 |
| --- | --- |
| 系统代理 | 你平时依赖 Windows 代理 |
| 不使用代理 | 排查是否是代理导致请求失败 |
| 手动代理 | 使用特定代理地址 |

手动代理模式下的“绕过局域网”会影响访问 NAS、局域网媒体服务器等本地地址。访问内网失败时，确认代理没有把本地请求送到外部。

改完代理后，一次只测试一个目标。不要同时切换代理、DNS、媒体服务器地址和播放器内核，否则无法知道是哪一项产生了变化。

## TMDB 设置

### 密钥

“设置 → 首页 → TMDB 密钥”留空时使用软件内置密钥；填写自己的 TMDB API Key 后，刮削请求会使用你的密钥。

如果只有你自己的密钥失败，检查密钥状态、账户限制和请求额度；如果所有用户都无法访问，更可能是网络或 TMDB 服务状态。不要把密钥原文放进日志反馈。

### 语言和区域

TMDB 区域代码、默认语言和默认图片语言影响资料和图片的选择偏好，不负责修复网络连接。

中文内容可以先使用 CN、zh、zh 作为对照。遇到英文标题或海报，不要马上判断为刮削失败，先检查这些偏好。

### 图片加载

标题和简介能显示，但海报、背景图或场景图加载失败时，可能是图片域名、缓存或网络策略问题，不一定是 TMDB 搜索接口失败。可以先降低图片质量、关闭某个来源的场景缩略图，或清理后重新生成缓存。

## 媒体服务器地址和权限

连接 Emby、Jellyfin、Plex、极影视或飞牛影视时，分别检查：

- 地址是否包含正确协议和端口；
- 用户名和密码是否正确；
- 账号是否能读取对应媒体库；
- 服务器是否允许当前设备访问；
- 是否选错了媒体库模式或直连模式。

飞牛影视默认端口是 8005，不是 5666。非自建服务器通常不要开启媒体库模式，避免读取全部媒体信息。

## 在线媒体站点

在线媒体站点来自外部来源。站点列表能打开但搜索失败，可能是站点接口或站点内容问题；搜索有结果但播放失败，优先换线路或换站点。

在线媒体的标准流程是普通浏览或搜索 → 尝试匹配 TMDB → 在统一媒体详情或兜底弹窗中选择线路 → 播放，见[搜索、线路与播放](/docs/media/online/source-selection)。不要把某个站点失效当成播放器整体故障。

## 代理改了仍然失败

按下面顺序收集信息：

1. 记录失败的具体服务和时间；
2. 用浏览器或服务端工具做对照；
3. 测试系统代理、直连或手动代理中的一个变化；
4. 确认本地文件是否仍可播放；
5. 打开 Debug 日志复现一次；
6. 脱敏后参考[日志导出与反馈](/docs/troubleshooting/logs-and-feedback)发送。

不要在反馈中发送代理密码、TMDB Key、媒体服务器密码或完整的私人地址。

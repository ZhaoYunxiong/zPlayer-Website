# 故障排查：先找到问题发生在哪一层

zPlayer 的“看不到、播不了、信息不对、同步失败”通常不是同一个问题。先把现象归类，再做一个最小测试，往往比连续修改十几个设置更快。

## 先按现象找入口

| 你看到的现象 | 优先查看 |
| --- | --- |
| 媒体库里没有来源或文件 | [媒体库为空](/docs/troubleshooting/library) |
| 能看到文件，但首页没有海报或内容 | [扫描或刮削失败](/docs/troubleshooting/scraping) |
| 首页或媒体详情加载很慢、网络请求失败 | [网络与 TMDB](/docs/troubleshooting/network-and-tmdb) |
| 黑屏、花屏、卡顿、音画不同步 | [播放失败、黑屏、卡顿](/docs/troubleshooting/playback) |
| 字幕、弹幕或声音不正常 | [字幕、弹幕或音频异常](/docs/troubleshooting/subtitle-and-danmaku) |
| 购买、登录或观看记录不同步 | [账户、授权与同步问题](/docs/troubleshooting/account-and-sync) |
| 不知道该提供什么给开发者 | [日志导出与反馈](/docs/troubleshooting/logs-and-feedback) |

## 一套通用排查顺序

1. 记录 zPlayer 版本、Windows 版本和问题发生的大致时间。
2. 写下最短复现步骤，例如“打开某个来源 → 点开第一集 → 选择第二条线路 → 黑屏”。
3. 判断问题只发生在一个文件、一个来源，还是所有媒体都发生。
4. 用一个简单的本地视频或小目录做对照测试。
5. 一次只调整一个设置，重新打开同一个媒体验证。
6. 仍无法解决时，收集脱敏日志和专用诊断信息。

## 最小测试为什么重要

如果本地小视频可以播放，而某个网络片源不行，问题更可能在网络、线路、权限或服务端；如果所有视频都黑屏，才优先怀疑播放器内核、解码或显卡环境。

同样地，文件服务能看到文件但首页没有海报，说明“连接和扫描”可能已经成功，下一步应检查内容类型、文件命名、TMDB 和刮削，而不是重新添加同一个来源。

## 反馈前要准备什么

尽量一次提供：

- Windows 版本和 zPlayer 版本；
- 来源类型、连接方式和是否为媒体服务器；
- 当前媒体的文件名或作品名；
- 发生时间和最短操作步骤；
- 是否可以稳定复现；
- 脱敏后的日志、媒体详情播放诊断或首页刮削信息导出。

不要在日志或截图中公开密码、Cookie、API Key、访问令牌、邮箱授权码、完整私人地址和不希望泄露的文件路径。

具体反馈方式见[日志导出与反馈](/docs/troubleshooting/logs-and-feedback)。

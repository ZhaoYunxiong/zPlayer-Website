# 播放失败、黑屏、卡顿：先把播放链路拆开

播放一部媒体至少经过“来源 → 地址或文件 → 播放内核 → 解码 → 渲染 → 音频/字幕/弹幕”这些环节。排查时不要把所有环节一起改掉。

## 先做最小对照测试

1. 关闭当前媒体，打开一个确定正常的本地小视频；
2. 如果本地视频正常，再回到出问题的网络来源或在线线路；
3. 同一部媒体有多个来源时，换另一个文件、服务器或线路；
4. 暂时关闭弹幕、字幕动画、着色器和额外滤镜；
5. 记录问题出现的时间、媒体来源和当前片源。

这样可以快速判断是“整个播放器有问题”，还是只有某一个文件、来源或线路异常。

## 点击播放没有反应或播放失败

### 本地文件

- 确认文件没有被移动、重命名或删除；
- 用 Windows 资源管理器确认文件可以读取；
- 用另一个播放器做一次对照；
- 检查 zPlayer 是否识别该扩展名；
- 如果是外接硬盘或网络挂载盘，确认设备没有休眠或断开。

如果只有一个文件失败，可能是文件损坏、编码异常或容器格式问题；如果所有本地文件都失败，再继续看解码和渲染。

### NAS、媒体服务器和在线线路

- 确认来源还在线，账号仍有读取权限；
- 确认播放的是正确的来源，不要把同名的本地文件和服务器文件混在一起判断；
- 在线媒体优先切换另一条线路；
- Emby、Jellyfin、Plex 等服务确认服务端没有限制当前设备；
- 非自建媒体服务器优先使用直连模式，不要为了“完整显示”开启媒体库模式。

在线媒体的搜索结果能显示，不代表每条线路都能播放；线路本身可能过期或被站点限制。

## 黑屏、花屏或画面不完整

先按下面顺序恢复：

1. 关闭当前着色器、滤镜和补帧处理；
2. 关闭弹幕，改用最简单的字幕轨道；
3. 在“设置 → 解码”中暂时使用 MPV 默认配置；
4. 硬件解码先测试自动或软件解码；
5. 仍然黑屏时，再尝试切换渲染模式或视频输出驱动；
6. 重新打开同一个文件验证。

如果只有某一类编码、某一个显卡或某一个视频出现问题，记录视频编码、分辨率、显卡型号和驱动版本。不要把“关闭滤镜后能播放”当成最终解决方案，它只是帮助定位问题来源。

## 卡顿、掉帧或音画不同步

### 本地视频

观察播放时 CPU、GPU 和内存占用：

- CPU 很高：先关闭动态字幕、动画、滤镜或高成本着色器；
- GPU 很高：降低画质处理，检查硬件解码是否正常；
- 两者都不高但仍卡：检查存储设备读取速度和后台任务；
- 只有高码率视频卡：尝试软件解码、硬件解码和另一个渲染模式做对照。

### 网络视频

- 先换线路或降低码率；
- 确认网络速度足够，Wi-Fi 设备没有切换频段或丢包；
- 检查服务器是否在转码、限速或同时被多人使用；
- M3U8 片源可以查看是否需要实验性的缓冲加速；
- 不要同时开多个下载、刮削和播放任务进行测试。

音画不同步时，先关闭字幕、弹幕和滤镜，判断是视频本身、解码负载，还是附加内容造成的。

## 声音没有、太小或切错音轨

- 检查系统输出设备和 Windows 音量；
- 检查播放器是否静音、音量是否被限制；
- 打开音频轨道列表，确认选择了正确语言和声道；
- 暂时关闭均衡器和特殊音频处理；
- 如果只有蓝牙或 HDMI 输出异常，换系统输出设备做对照。

播放器音频设置见[音频与均衡器](/docs/player/audio)；不要用提高最大音量的方式掩盖系统输出或片源音轨问题。

## 字幕或弹幕导致卡顿

先关闭字幕动画、弹幕和复杂 ASS 样式。如果画面恢复流畅，再逐个打开：

1. 只开一条普通字幕；
2. 再开字幕动画；
3. 最后加载弹幕或多条字幕；
4. 找到导致卡顿的那一项后降低复杂度。

多条字幕、实时翻译、弹幕补帧和着色器同时使用时，设备负载会明显增加。相关处理见[字幕、弹幕或音频异常](/docs/troubleshooting/subtitle-and-danmaku)。

## 用媒体详情里的播放诊断

如果同一媒体始终失败，从媒体详情的操作中打开“播放诊断”，记录：

- 当前来源和片源；
- 媒体地址类型或文件信息；
- 播放内核、硬件解码和渲染设置；
- 错误表现以及发生时间。

播放诊断适合结合日志一起反馈，见[日志导出与反馈](/docs/troubleshooting/logs-and-feedback)。

## 反馈前的最小组合

请尽量提供：

- 一个可以稳定复现的文件、作品或线路；
- “本地正常/网络异常”或“所有媒体都异常”的对照结果；
- 关闭滤镜、切换硬件解码后的结果；
- 显卡和驱动版本；
- 媒体详情播放诊断和脱敏日志。

不要在日志中公开完整媒体服务器密码、令牌、Cookie 或私人地址。

# 日志导出与反馈：把“不能用”变成开发者能复现的信息

如果问题可以稳定复现，日志通常比一句“播放不了”更有帮助。请尽量在问题刚出现后收集，不要先连续重启或清空所有配置。

## 推荐反馈内容

请尽量提供：

- Windows 版本；
- zPlayer 版本；
- 问题发生的日期和准确时间；
- 媒体来源类型和连接方式；
- 当前作品、季数、集数或文件类型；
- 从打开软件到出现问题的最短步骤；
- 是否可以稳定复现；
- 本地文件或其他来源是否正常；
- 脱敏后的日志或专用诊断文件。

例如，“Windows 11，Jellyfin 直连模式，打开某剧 S01E02 后切换第二条片源黑屏；同一文件在本地正常，关闭硬件解码后仍然黑屏”，比“Jellyfin 不能播放”更容易定位。

## 收集日志

1. 打开“设置 → 调试”；
2. 临时将日志级别改为 Debug；
3. 按最短步骤复现一次；
4. 打开“文件夹 → 打开”进入日志目录；
5. 找到问题发生时间附近的日志；
6. 反馈完成后把日志级别恢复为 Information。

Windows 默认日志目录通常是：

%APPDATA%\zPlayer\logs

如果没有生成日志，先复现一次再打开文件夹。

## 不同问题对应的专用材料

| 问题 | 额外材料 |
| --- | --- |
| 标题、海报或剧集匹配错误 | 首页右上角菜单中的刮削信息导出 |
| 播放失败或片源异常 | 媒体详情中的播放诊断 |
| Bangumi、Trakt 或媒体服务器不同步 | 同步类型、操作方向和同步异常时间 |
| 字幕或弹幕异常 | 字幕/弹幕来源、轨道和关闭附加内容后的结果 |

专用材料和日志一起提供时，开发者更容易判断问题属于来源、匹配、网络还是播放器。

## 分享前一定要脱敏

请检查并删除：

- API Key、访问令牌和 Cookie；
- 媒体服务器用户名和密码；
- 邮箱地址、邮箱授权码和下载器密码；
- 完整 NAS、内网或公网地址；
- 私人文件路径、家庭成员姓名和其他个人信息；
- 不希望公开的媒体文件名。

如果日志里同一敏感信息出现多次，要全部替换，不要只删第一处。截图也要遮挡账号、地址和通知内容。

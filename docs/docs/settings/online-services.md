# 在线服务：先分清“使用别人”还是“让别人连接”

这里会遇到几种看起来都和网络有关、实际用途完全不同的设置：

1. 在线媒体：从站点浏览或搜索内容并播放；
2. 外部媒体来源：连接自己的 NAS、Emby、Jellyfin、Plex 等；
3. 媒体服务器共享：让其他设备连接 zPlayer 当前能访问的媒体；
4. 投屏：让 zPlayer 发现或使用局域网中的播放设备；
5. RSS：订阅资源更新，并可选地交给下载器。

外部媒体来源的添加流程在[文件服务](/docs/media/file-services)，本页主要解释“设置”里这些网络选项的作用。

## 在线库设置

入口是“设置 → 在线库”。

### 默认加载站点

在线库可以配置一个默认站点。设置后，打开在线库时会优先加载它；留空或站点不可用时，仍然可以手动选择其他来源。

软件提供的六类站点扩展，区别主要在于来源格式和配置方式：Maccms、JS 爬虫、TVBox、IPTV、Miru、Kazumi。它们最终做的事情是一样的——把站点中的可播放媒体展示出来——不需要把六类都配置一遍。

如果你只是想找一个容易上手、互联网上资源较多的来源，可以优先尝试 Maccms 站点。站点本身的稳定性和内容合法性需要你自行判断。

### 站点自动更新

默认开启。开启后，zPlayer 会在需要时更新站点信息，让站点列表和扩展配置保持较新状态。

如果你在受限网络中频繁遇到站点更新失败、启动时等待较久，可以暂时关闭；这不会删除已经配置的站点。

### 在线媒体的打开逻辑

在线媒体会先尝试从 TMDB 查找元数据。匹配成功后进入统一媒体详情页，在线线路和剧集会在详情页中选择；TMDB 找不到匹配时，软件会自动显示简易的线路与集数选择弹窗作为兜底。

因此不需要在设置中切换“详情模式”和“直接线路模式”。正常结果优先使用完整的详情体验，无法匹配的站点结果仍然可以通过弹窗直接播放。

## 在线媒体真正怎么用

六种站点类型只是“数据从哪里来”的区别，不要把它们理解成六套完全不同的播放器。

最常用的路径是：

1. 打开在线库，普通浏览站点，或者搜索作品；
2. 点击作品，等待 zPlayer 尝试匹配 TMDB；
3. 匹配成功时，在统一媒体详情中确认剧集和清晰度并选择线路；
4. 匹配失败时，在简易弹窗中选择线路和集数；
5. 点击播放；
6. 播放失败时回到详情或弹窗，切换另一条线路。

详细的结果展示、线路切换和播放行为见[搜索、线路与播放](/docs/media/online/source-selection)。在线媒体的搜索结果不是本地文件，也不会自动变成你的本地媒体库。

## zPlayer 对外提供的共享服务

入口是“设置 → 媒体服务器”。这里不是添加 Emby 或 Jellyfin，而是把 zPlayer 能访问的媒体，通过协议提供给其他设备。

### 三种快速共享

| 服务 | 适合连接的设备 | 默认端口 |
| --- | --- | ---: |
| WebDAV | 支持 WebDAV 的播放器、文件管理器和其他客户端 | 62106 |
| FTP | 支持 FTP 的文件管理器或播放器 | 62103 |
| DLNA | 局域网电视、播放器和投屏设备 | 62104 |

打开对应服务后，页面会显示链接或访问信息。端口只有在与其他程序冲突、或你明确规划了网络端口时才需要改。

### 用户验证

媒体服务器设置里可以添加用于共享服务登录的用户名和密码。共享服务默认不应被当成公网网盘使用：

- 只在可信局域网中使用时，也建议配置一个用户；
- 如果设备会暴露到公网，务必开启 WebDAV 或 FTP 的登录验证，并配合防火墙；
- 不要把共享链接、用户名和密码一起发到公开群组；
- DLNA 更适合局域网发现和播放，不要把它当成带强认证的远程服务。

### WebDAV、FTP 的服务参数

共享区是快速启停入口，下面的服务设置用于更细的参数：

- 文件传输端口默认是 62102；
- WebDAV 服务可以调整端口、API 路径和登录验证；
- FTP 服务可以调整端口和登录验证；
- DLNA 服务可以调整端口；
- Windows 防火墙入站规则可以通过页面按钮配置。

除非你知道客户端要求的路径，否则不要随意修改 WebDAV API 路径。改过端口后，必须使用页面重新显示的链接，旧链接不会自动跟着你手动输入的端口变化。

::: warning 共享服务的安全边界
不要直接把 WebDAV、FTP 或管理端口映射到公网。先在局域网测试，再按路由器、防火墙、账号验证和最小权限的顺序规划远程访问。
:::

## 投屏设置

入口是“设置 → 投屏”。

| 设置 | 作用 | 默认 |
| --- | --- | --- |
| 设备名称前缀 | 其他设备发现 zPlayer 时看到的名称前缀 | zPlayer |
| 自动播放投屏而不用询问 | 收到投屏请求后是否直接播放 | 关闭 |
| DLNA 投屏 | 是否启用 DLNA 投屏相关能力 | 开启 |

设备名称建议改成容易辨认的名字，例如“客厅电脑”。自动播放适合你完全信任局域网设备的环境；多人共用网络或不希望被突然打断时，保持关闭更稳妥。

投屏入口在媒体详情或播放相关操作中，设置页只负责设备名称、确认行为和 DLNA 能力开关。

## RSS：订阅和自动下载

RSS 设置虽然也属于在线服务，但它的核心不是在线播放，而是“发现更新 → 可选下载 → 放入媒体库”。

完整设置在“设置 → RSS 订阅”，包括：

- 订阅地址、标题、内容类型和是否聚合；
- RSS 自动刷新间隔，默认 10 分钟；
- 自动下载开关，默认关闭；
- 下载器、远程 API、远程下载路径和分类；
- 命中即跳过的正则过滤规则；
- 下载后媒体刮削和媒体挂载路径；
- 番剧缺集自动补全；
- 下载报告邮件。

RSS 的设置较多，集中说明放在[AI、Whisper、RSS 与模块](/docs/settings/ai-and-modules)。如果你只是要浏览或播放在线视频，不需要配置 RSS。

## TMDB 和网络代理不要混着改

TMDB 密钥、语言、图片质量属于[首页设置](/docs/settings/home)，控制元数据刮削；网络代理属于[账户、网络与其他](/docs/settings/account-and-network)，控制网络请求怎么出去。

遇到刮削失败时，先判断是 TMDB 无法访问、来源本身无法访问，还是文件名匹配不准确。不要为了修复本地文件播放问题去修改在线库或共享服务设置。

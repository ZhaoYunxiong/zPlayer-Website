# 调试与日志：让问题变得可以定位

入口是“设置 → 调试”。这里主要控制日志详细程度和日志文件夹，通常只在排查问题时使用。

## 日志级别

可选级别从详细到简略大致是：

| 级别 | 适合什么时候用 |
| --- | --- |
| Debug | 临时复现问题，记录最详细的过程 |
| Information | 日常使用，默认级别 |
| Warning | 只关注警告及更严重的问题 |
| Error | 只关注错误 |
| Fatal | 只保留致命错误 |

建议平时使用 Information。Debug 日志会更多，长期打开会增加日志体积，也可能记录更多来源地址、文件路径或请求过程。

## 推荐的反馈流程

遇到问题时，按一次完整流程收集信息：

1. 记下 zPlayer 版本、Windows 版本和问题发生的大致时间；
2. 记录你刚才做了什么，例如“添加 NAS 后首页不显示”或“切换第二条线路后播放失败”；
3. 临时把日志级别改为 Debug；
4. 完整复现一次，不要连续重复几十次；
5. 打开日志文件夹，找到对应时间段的日志；
6. 把日志中的 API Key、访问令牌、密码、邮箱、内网地址和私人文件路径脱敏；
7. 反馈完成后把日志级别恢复为 Information。

如果问题只发生在某一个来源，反馈时同时说明来源类型、连接方式和是否只有这一条来源异常。不要只发一句“不能用”，这样很难判断是网络、权限、解析还是播放器的问题。

## 日志文件夹

点击“文件夹 → 打开”即可让系统打开日志目录。Windows 默认位置通常是：

%APPDATA%\zPlayer\logs

如果页面提示没有生成日志，先复现一次问题，再重新打开日志文件夹。

## 哪些问题还要看其他信息

日志可以说明软件做了什么，但不一定能替代对应功能里的专用信息：

| 问题 | 优先查看 |
| --- | --- |
| 媒体没有匹配、标题或海报错误 | 首页右上角刮削信息导出、[扫描与刮削](/docs/media/home/scraping) |
| 播放器黑屏、卡顿或解码失败 | [播放内核、解码与硬件加速](/docs/player/engine-and-decoder) |
| 线路播放失败 | [搜索、线路与播放](/docs/media/online/source-selection) |
| Bangumi、Trakt 或媒体服务器进度不同步 | [同步异常排查](/docs/sync/troubleshooting) |
| 字幕、弹幕或音频异常 | [播放器章节](/docs/player/)中的对应页面 |

媒体详情中的播放诊断、首页中的刮削信息导出，分别记录了更贴近具体对象的额外信息。它们属于对应功能流程，不需要在调试设置里长期打开 Debug。

::: warning 分享日志前一定要脱敏
日志可能包含文件名、目录、服务器地址、用户名、请求 URL 和错误上下文。API Key、访问令牌、密码、邮箱授权码和私人媒体路径都不要原样发送。
:::

## 恢复默认

如果改过日志级别后不确定原来的值，恢复为 Information 即可。日志文件本身不会因为切换级别自动删除；需要清理时，请在确认不再需要排查后，再按系统或文件管理器的方式处理旧日志。

# 播放内核、解码与硬件加速：遇到黑屏卡顿先看这里

视频能否顺畅播放，不只取决于文件大小。封装格式、视频编码、音频编码、字幕、显卡驱动、网络速度和实时画质处理，都会参与最后的播放链路。

## 第一次播放先不要改设置

建议先用默认播放内核、默认渲染和默认硬件解码播放同一个片源。只有在明确出现黑屏、花屏、卡顿、音画不同步或 CPU/GPU 占用异常时，才开始逐项调整。

每次只改变一个选项，并重新打开当前媒体测试。一次改很多项，往往能“碰巧修好”，却很难知道下次遇到问题该恢复哪一项。

## 硬件解码和软件解码怎么选

硬件解码会尽量把视频解码工作交给显卡，通常能降低 CPU 占用；软件解码由 CPU 完成，兼容性排查时更容易作为对照组。实际效果取决于显卡、驱动和视频编码格式。

可以这样判断：

| 现象 | 建议 |
| --- | --- |
| 普通视频播放正常 | 保持默认，不必为了“更专业”修改 |
| CPU 很高但 GPU 较空闲 | 尝试硬件解码，并重新打开视频 |
| 开启硬件解码后黑屏、花屏或闪烁 | 切回软件解码测试，随后检查显卡驱动和输出模式 |
| 只有某一种编码出问题 | 在媒体属性中记录编码信息，再针对该片源测试 |
| 网络视频持续卡顿 | 先确认网络和服务端输出，再调整解码；解码设置无法弥补带宽不足 |

设置修改后最好完全停止并重新开始播放，避免旧的解码状态影响判断。

## 从媒体属性判断问题在哪里

在播放器菜单中打开“媒体属性”或“播放统计”，可以查看当前播放链路和媒体信息。重点记录：

- 视频和音频编码；
- 分辨率、帧率和码率；
- 当前使用的音频、字幕和视频轨道；
- 本地文件还是网络流；
- 播放时 CPU、GPU 和缓冲状态。

同一部作品换一个文件就正常，通常说明问题在具体文件、编码或来源；所有视频都异常，才更像播放器设置、核心或驱动问题。

## 设置项在哪里

解码内核、渲染模式、视频输出驱动、GPU 上下文、硬件解码、音频输出驱动以及 M3U8 缓冲加速，都可以在[播放、解码与画质设置](/docs/settings/playback)中查询。高级选项不建议在没有现象时开启或关闭。

如果片源访问失败、权限不足或媒体服务器返回了错误地址，解码器并不能解决来源问题。此时请先回到[媒体详情](/docs/media/home/media-detail)确认来源和播放诊断信息。
